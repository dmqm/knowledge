## 1. 协作方式（最高频的摩擦点）

**现象**：agent 按 brainstorming 技能逐个提问，用户多次打断。

- `ses_ec0340` 用户原话：「我觉得这些你不需要问我，这些都是很常见的，你一次性完成给我看结果」
- `ses_ebdbe5` 用户原话：「不要再问我这么多，我要你推荐，要么一次性问完」
  （此前 agent 连续单问了两轮：先问"为什么想学"，再问"学完想做什么"）
- `ses_ebdbc1` 用户原话：「我的意思我有别的 App 都新闻」（agent 又在追问内容来源）

**反例（做对了）**：`ses_ec0340` 用户说"课程内容都太浅了"后，agent 改用
`question` 工具**一次问完**深度标准，用户认可并继续。

**经验**：

- 默认**先给方案 / 直接做完，再看结果**；把澄清提问压到最少。
- 必须问时**一次问完**（batch），且只问"会显著改变大量工作走向"的关键分叉。
- brainstorming 第一步保留"想跳过提问就说一声"的选项——但仅此不够，用户仍会觉得多。

用户的稳定口头偏好：**直接做完 / 一次性完成 / 我在手机上看 git 结果**。

## 2. 内容生产（`teach` 课程）

**技能位置**：`teach` 与 `show-me` **不在** harness 的 `available_skills` 里，
实际装在 `C:\Users\admin\.agents\skills\teach`（`show-me` 同目录）。早期会话反复
找不到它、每次都要手动 glob（`ses_ec0340`、`ses_ec47ae`、`ses_ebdbe5`）。**应写进 AGENTS.md。**

**深度 = 整本书**：用户三次升级要求：

1. 首批 2 讲 → 「两讲也太少了。。。这是一本书」（`ses_ec0340`）
2. 扩到 11/14 讲 → 「课程内容都太浅了。。。这是一本书啊」（`ses_ec0340`）
3. 最终：每讲正文 **2500–4000 字**，写"机制 + 真实案例 + 决策链"，而非概念罗列。

**经验**：一本书的课程，**一开始就按章节展开 + 单讲 2500–4000 字**，别先交付浅稿再返工。

**图文并茂**：`ses_ec0340` 用户明确要图 → 每页一张**内联 SVG 示意图**
（离线可用、主题自适应、无硬编码颜色）；`ses_ebdc67` 摄影课改用 Wikimedia
公共领域**真实照片**。图要放在概念引入处 + 一句中文图注。

**资源必须查证**：不许凭记忆编 URL，逐个 websearch/webfetch 验证可达
（`ses_ebdbe5`、`ses_ebdc67`）。

**偏好要落盘**：把"要图 / 要深"写进课程笔记或 learning-record，让后续会话延续
（`ses_ec0340` 结束时确有记录）。

## 3. Agent / 工具编排

- **`subagent` 不能在 `execute`（code mode）里调用**，只能在顶层直接并行调用
  （`ses_ebdbe5` 撞到过）。课程写作大量并行（一次 2/5/7/10 个），但只对互相独立的任务有效。
- 主动用 **`compress`** 压上下文（全会话库出现 26 次），尤其在**派发大量 subagent 前**。
- **一致性用脚本核验**：定义 exemplar 讲，subagent 照它对齐；然后脚本检查
  class 是否存在、测验脚本是否逐字一致、无硬编码颜色、导航链接是否可达、SVG 是否存在。
- **浏览器实测**：Python/Playwright 不可用时用系统自带 Edge 无头截图验证渲染。
- **`write` 超大内容会 JSON 解析失败**（`ses_ebdbe5`）→ 分块/减小单次写入量。

## 4. 工程 / 环境（Windows）

- **PowerShell 引号**经常被搞乱 → 写成临时 `.mjs` 脚本再 `node` 跑（多次出现）。
- **编码**：PowerShell 默认编码曾把临时文件里的 SVG 弄坏（假警报）；读写显式指定 UTF-8。
- **git 假改动**：`core.autocrlf` 导致 `status` 显示 modified 但 `diff` 为空
  （`ses_ebdbe5`、`ses_ec0340`）——先 `git diff` 确认是否真有内容变化。
- **git 凭据卡死**：`credential.helper` 指向会挂起的 `helper-selector`，首次 push
  靠 URL 内嵌 token 才成功；改为直接指定 GCM 后正常（`ses_ebfc38`）。
- **网络（中国大陆）**：Wikipedia、Reddit 不可达（`ses_ebdc67`）；选资源先探可达性，
  优先**内联、可离线**的呈现，而非外链图片。
- **发布流程**：改内容 → `git push` → GitHub Actions 自动构建发布；**本地不用起服务器**
  （用户强调过两次：`ses_ec0340`）。站点：`https://dmqm.github.io/knowledge/`。
- **服务器重启**会打断会话（synthetic "server restarted"）——续做要幂等，别重复已完成的工作。

## 5. 仓库约定（`AGENTS.md` 已有，要点复述）

- 零第三方依赖，只用 Node 内置模块。
- 两种模式（`node server.mjs` 服务器 / `dist/` 静态）共用同一份前端，都要能跑。
- 静态构建用**相对路径**（可能挂在 `/<repo>/` 子路径）。
- 不提交 `data/`、`config.json`、`dist/`、`courses/.trash/`；目录名以 `.` 开头 = 留一手。

## 6. 可复用清单

- **开新课程前**：查证书/资源真实存在且 URL 可达；确认深度标准（默认：整本书、单讲 2500–4000 字）。
- **动笔前**：先写一个 exemplar 讲，subagent 照它对齐格式与深度。
- **提交前**：跑一致性脚本（无硬编码颜色 / 测验一致 / 链接可达 / 图存在）+ 排除 CRLF 假改动。
- **沟通**：能直接做完就直接做完；必须问就一次问完。

1. 把 **§1（少问、一次问完、直接做完）** 与 **§2（深度 + 图文并茂 + 查证）** 写进
   仓库 `AGENTS.md` 或全局 `~/.config/opencode/AGENTS.md`。
2. 把 **`teach` / `show-me` 的技能路径**写进 `AGENTS.md`，避免每次手动查找。
3. 把"图文并茂、深度、资源查证"作为课程默认要求固化。
