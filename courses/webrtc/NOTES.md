# 工作笔记

## 读者偏好

- **手机阅读为主**，一讲要能在通勤路上读完；但明确要求「深入理解」，所以宁可长一点、讲机制，也不要概念清单。
- 已有后端 / 运维背景（Docker、VPS、Tailscale、自托管栈），没有音视频经验。类比可以从「网络运维 / 服务端」借，不要用前端框架类比。
- 讨厌答非所问与含糊其辞。凡是「看情况」的结论，必须给出判断依据与阈值。
- **事实纪律**：不编数字。经验数据必须标年份与来源；规范结论必须落到 RFC 编号与章节。
- 习惯**看发布后的结果**（git push → GitHub Pages），不怎么看本地预览。改完记得推。

## 写作约定（本课）

- 图一律内联 SVG，用 `.figure` 里的 CSS 变量类（`t-muted` / `s-accent` / `f-wash` …），**绝不写死颜色**，否则暗色模式会瞎。
- 每讲至少一张图；讲「流程」用左右两栏时序，讲「结构」用嵌套矩形。
- 测验选项**字数尽量对齐**（中文按字符数对齐），正确项位置打散，不靠格式暗示答案。
- 每讲结尾给一份**一手资料**（RFC / W3C / 公开测量），并说明「读哪一节」。
- 引用外部链接前先 `curl -I` 验证；本项目环境下 `webrtc.org`、`webrtc.googlesource.com`、`wiki.wireshark.org` 不可达，**不要引用**。

## 课程弧线（写新讲时保持这条线）

1. 定位：它不是协议，是一套强制约定 + 一层 API（本讲）
2. 协商：SDP 与 offer/answer 是状态机，不是配置表
3. 连通：ICE 的候选、检查、提名
4. 穿越：NAT 的真实行为与失败模式（含中继成本）
5. 加密：DTLS-SRTP 与身份绑定
6. 容错：RTP 打包、NACK/FEC、抖动缓冲
7. 自适应：拥塞控制与码率分配
8. 决策：拓扑、容量、可观测性、上线检查表

每讲开头要回指上一讲的结论，结尾要抛出一个「下一讲才能回答」的问题。
