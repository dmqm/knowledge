# 课程起点：先修知识与真实目标

旅行者主动提出「想深入理解 WebRTC」，经确认选择做成系统课程而不是一次性讲解。已声明的背景：后端 / 运维能力强（Docker、自托管服务、VPS、Tailscale），但**没有音视频领域经验**，也自述不想先看一坨 API 教程。

这意味着课程不能从 `new RTCPeerConnection()` 讲起——那会把「为什么」全部跳过。起点定为「它到底在解决什么问题、哪些部分被标准化了」，把 API 当作结论而非入口。同时可以利用已有的网络运维直觉（NAT、端口、防火墙、带宽计费）作为锚点，这是最容易迁移的部分。

后续设计判断：跳过编码原理，重点压在 ICE/NAT、DTLS、拥塞控制三段，因为这三段既是故障高发区，也是「看教程抄不会」的部分。
