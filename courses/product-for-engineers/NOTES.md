# Notes

- 主题：工程师的产品思维（从写代码到定义产品）。工作区根目录：`courses/product-for-engineers/`。
- 学习者画像：**后端开发 / 架构师**，想补"基本的产品技能"，**不转岗**，目标是让自己在现有工作里具备"判断该做什么、值不值得做"的能力。
- 阅读偏好：手机端优先、窄屏排版清晰。**正文约 2500–4000 字，深度优先**——用户在别的课程里明确抱怨过"太浅了……这是一本书啊"。每讲要把机制、案例、数据与论证链条写透，不做浅层摘要。
- 立场：不教设计工具、不教转岗求职。重心是**判断力**（问题定义、机会评估、验证、优先级、协作沟通）。
- 语气：务实、直接，用工程语言类比；尊重技术人的既有心智模型（架构、权衡、复杂度），把产品概念映射上去。
- 事实纪律：不编数字、不编引文。凡引用书 / 文章 / 数据，一律指向 RESOURCES.md 里的一手资料。
- 讲义互相之间用 HTML 锚点链接；每讲末尾推荐一条一手资料。
