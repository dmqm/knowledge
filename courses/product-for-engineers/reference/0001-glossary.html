概念速查表

全课程共用的术语。所有讲义都以本表的措辞为准；遇到没收录的词，先回来这里补定义再用。想深入，每一讲末尾都有一手资料。

思维与目标

工程思维engineering thinking
给定一个问题，找出最好的解法。优化正确性、可靠性、效率、成本。题目是给定的。
产品思维product thinking
先追问问题值不值得解、是不是真问题。优化用户价值与业务结果。题目本身要被质疑。
产出output
你交付了什么——上线了几个功能、写了多少代码。容易度量，但与价值无关。
结果outcome
用户或业务真的发生了什么改变——任务变快、留存提高、成本下降。难度量，但才是有意义的。
交付陷阱build trap · Melissa Perri
组织用产出而非结果衡量成功，于是不断生产功能，却离用户的真问题越来越远。

团队与工作方式

功能团队feature team
被动接收一份功能清单 / 路线图并把它做出来。产品的成败不由它负责。本质是「功能工厂」。
赋能团队empowered team · Marty Cagan
接收的是要达成的结果（如「提高新用户首周留存」），自己负责发现问题、设计方案、验证结果。
发现 / 交付discovery / delivery
发现 = 决定「做什么」的工作（探问题、验假设）；交付 = 把确定要做的东西「做出来、上线、维护」。
塑形 / 下注shaping / betting · Shape Up
塑形 = 在投入前把粗糙想法打磨到「够粗、够确定、有边界」；下注 = 从候选里挑少数几件进固定周期做。
时间预算appetite · Shape Up
先定「愿意为这件事花多少时间」，再让方案迁就这个预算；而不是先估工时再决定做不做。

理解用户与需求

用户要完成的任务Jobs to Be Done (JTBD) · Christensen
用户不是「买产品」，而是「雇一个东西来完成某件事」。问「他雇它干什么」，而不是「他要什么功能」。
需求 vs 任务request vs job
需求是他提出的手段（「我要批量导出」）；任务是他真正想达成的进展（「我要找出那几个对象」）。
机会解决方案树Opportunity Solution Tree (OST) · Teresa Torres
从「目标」向下长：目标 → 用户机会（痛点 / 需求）→ 候选方案 → 假设实验。用来避免一上来就跳到方案。
假设assumption
你认为成立、但还没被证据支持的说法。产品里最贵的往往不是「实现错了」，而是「假设错了」。
最危险的假设riskiest assumption
如果它错了、代价最大的那条假设。验证要从它开始，而不是从最容易的那条开始。

验证与优先级

最小可行产品MVP · Lean Startup
用最小成本学到最多东西的那一版——目标是「拿到能改变决策的证据」，不是「少做一点上线」。
构建—度量—学习Build-Measure-Learn
精益创业的核心循环：先做出最小版本，度量真实反馈，据此决定坚持或转向（pivot）。
产品—市场契合PMF
产品真正满足了某类人的某项任务，用户愿意持续使用甚至离不开它。没有 PMF，再多的功能也留不住人。
RICEReach × Impact × Confidence ÷ Effort · Intercom
量化优先级：(触达人数 × 影响程度 × 信心) ÷ 工作量。好处是把分歧摊到四个明确因素上，不是替你决定。
Kano 模型基本型 / 期望型 / 兴奋型需求
把需求分类：基本型缺失会让人愤怒、做多也不会更满意；期望型越多越好；兴奋型超出预期、能带来惊喜。

负债与判断

产品债product debt
为了短期上线而欠下的体验债、逻辑债、一致性债。与「技术债」对应，同样会累积利息。
可行性 / 可用性 / 价值 / 商业可行性feasibility / usability / value / viability
Cagan 的四问：技术做得到吗（工程负责）、用户用得明白吗（设计负责）、用户真需要吗、业务算得过账吗（产品负责）。
