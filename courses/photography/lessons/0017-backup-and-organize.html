日常摄影实践 · 第 17 讲

备份与素材整理：拍完才是开始

照片在按下快门那一刻并不安全——它只是一段还在设备里的数据。这一讲把「拍完之后怎么办」变成一套你在这台 Windows 11 机器上真的能执行的流程。

← 上一讲 · 第 16 讲 · 城市与自然  ·  下一讲 · 第 18 讲 · 一个主题的拍摄项目 →  ·  曝光速查表  ·  词汇表

前十六讲讲的都是「怎么拍得更好」。这一讲讲一件听起来不酷、却决定了你能留下多少的事： 拍下来的东西，怎么从设备里安全地变成你的东西。

先说一句实话。你这台机器上只有两台拍摄设备——iPhone Air 和 DJI Osmo Pocket 4。问题在于，它们都是会坏、会丢、会被格式化的东西。 设备摔一次、卡坏一块、「腾空间」时顺手清空了卡——照片就没了。而且这类事不发生在按下快门的当天， 往往发生在三个月后你终于想起来整理素材的那天。

一、拍完才是开始：一张照片在哪儿才算存在

一张照片从「存在」到「安全」，中间有一段路要走完。我们把它拆成四段，每段都有一个明确的失败点：

  1. 在设备里。风险是设备损坏或误删。
  2. 在设备外第一份。已导入电脑，挡住「设备丢了」。
  3. 在第二份。另一块盘、另一个地方，挡住「电脑的盘坏了」。
  4. 在作品里。你选出、命名、调过、导出成最终版本的那一张——只有它进入相册、头像、打印件。

关键判断只有一句：一份照片在「同一个地方」存在两次，它就只算一份。 拷到同一个硬盘的两个文件夹里不算备份——一次故障会同时带走两份。 而 iPhone Air 与 Pocket 4 的存储都本来就是会定期被清空的地方： 手机会提示你清理，Pocket 4 的内置 107 GB 也会在「该清了」时被格式化。 所以这两台机上的文件，默认状态就是临时的。

二、导入：两台机各走各的路

iPhone Air。最省事的是「照片」App 里直接导出：打开照片 → 全选 → 分享 → 存储到文件。优势是你可以只挑要的那几张，适合已经筛过一轮的情况。

要一次全量搬，用线更省事：USB 线连上 Windows 11，手机会作为便携设备出现， 里面是 DCIM 目录；更省操作的写法是手机上打开设置 → 照片 → 传输到 Mac 或 PC， 插上线后电脑的 DCIM 里就能看到当天的文件夹。需要提醒的是， AirDrop 是 Apple 生态的功能，Windows 上没有——别的教程里写「用 AirDrop 传过去」， 那是写给 Mac 用户的，别照抄。

还有第三条：iCloud 照片。Windows 上装 iCloud 客户端并登录后，iPhone 上的照片会同步到本地文件夹。 它适合「懒得手动搬」的日常，但同步是后台的、有延迟的， 重要的一批照片不能只靠它——你需要在电脑上确认它们真的到了。

Osmo Pocket 4。三条路各有用处：

  • USB 3.1 直连电脑：官方规格页写着 USB 3.1 有线传输最高 800 MB/s， 一批 DNG 用线搬是最快的。插上线后机器被识别为便携设备，照片在 DCIM 里。
  • microSD + 读卡器：卡插进读卡器插电脑，和普通 U 盘一样。卡被格式化后， 机器会重新建目录，照片落在 MISC/DCIM 一类的路径下（换卡时目录会变， 所以导入后第一件事是「全选 → 复制」，不要一张张拖）。
  • DJI Mimo：官方 App，手机连上机器后把素材导出到手机相册或直接分享。 它的定位是快速分享，不是备份。

导入时的三条纪律：

  1. 先复制，后整理。导入完成后不要在原卡或设备里改名、删除、排序—— 那是唯一的那一份，任何误操作都不可逆。整理应该在电脑的副本上做。
  2. 复制不是移动。把文件「剪切」到电脑，等于把设备上的那份删了。 正确做法是复制，确认电脑里能打开之后，再回去考虑要不要清设备。
  3. 先看格式，再决定处理方式。HEIF/JPEG 和 DNG 的后续动作完全不同，见本讲第五节。

三、命名与目录：让三个月后的你找得到

整理的核心目标只有一个：半年后你想找「去年秋天在那个公园拍的那张」时， 不用翻三个小时。这件事靠两样东西做到：文件夹负责粗分类，文件名负责细区分。

目录按年 → 月 → 单次拍摄三层：

D:\Photos\2026\10\2026-10-24_城市街拍\
D:\Photos\2026\10\2026-10-24_城市街拍\raw\      ← 原始文件（.heic / .jpg / .dng），只读不动
D:\Photos\2026\10\2026-10-24_城市街拍\export\   ← 你导出的成品
D:\Photos\2026\10\2026-10-24_城市街拍\select\   ← 选中的那几张
D:\Photos\2026\10\2026-10-24_城市街拍\edit\     ← 后期工程文件与旁车文件

把原始文件和成品分开放是这一节最重要的规矩。原始文件是不可再生的： 你改坏的成品可以重做，你删掉的原片回不来。而两类文件混在一起时，你迟早会手滑覆盖掉原片。

文件名用一套固定规则，让文件管理器按名字排序就等于按时间排序：

20261024_城市街拍_001.jpg
20261024_城市街拍_002.dng
20261024_城市街拍_003.dng
20261025_公园散步_001.heic

三段分别是日期（8 位）→ 主题 → 序号（3 位）。日期放最前面是刻意的： 排序时 20261024_ 排在 20261103_ 前面， 而 1024_ 和 1103_ 谁在前全看心情。序号固定位数， 是为了让 _010 排在 _09 前面而不是反过来。

主题词不要写太长，也不要追求「精确」。写 城市街拍、公园散步、 家人 这种一眼能认出来的词就够了； 真正想不通的问题（哪个公园、谁拍的）写在旁边的说明文件里—— 文件名太长，在各种软件里都会出问题。

四、两份副本：以及 Pocket 4 的存储怎么选

「两份副本」落地成三件事：设备上留着的那一份（临时，不是备份）、 电脑本地硬盘上的那一份（工作副本，命名、选片、后期都在这里做）、 另一个地方的那一份（移动硬盘、第二块内盘或云端，挡住「电脑坏了」「被偷了」「误格式化」）。

做这件事有个省心的技巧：用同步代替复制。 把工作副本的整个 Photos 文件夹做成一个同步目标（第二块内盘、移动硬盘， 或 Windows 自带的 OneDrive 同步文件夹），每周只需插上盘、让它跑一次，就完成了一次异地副本。 这比「每周手动复制几百个文件」可靠得多——人靠不住，脚本和客户端靠得住。

Pocket 4 的内置 107 GB 与 microSD，怎么取舍

官方规格页写得很清楚：内置 107 GB，另可插 microSD（最大 1 TB）。 两种用法性质不同：

做法好处代价 / 风险
只用内置 107 GB 容量大、连续写同一块盘；不占卡位，出门只带机身也能拍很久 素材在同一块存储上：坏了、丢了、格式化了，全都没
只用 microSD 卡可以一卡一卡换，容量想加就加；卡格式化后电脑上直接读 容量受卡限制（1 TB 是官方规格的可用最大值，还要看卡的写入速度）； 机器要先插卡才能存
两张卡同时写 看起来「双保险」 不推荐。同时写多了一条写入链路，一旦中途出问题两边都可能受影响， 也会拖慢写入、耗电更多。官方规格页只把内置存储与 microSD 列为两个存储位置， 没有把双写当成一项功能来介绍

那么只有一张卡的时候该怎么拍？有一个不会出错的顺序，值得背下来， 因为「插了卡但机器没在往卡上写」是极常见的坑：

  1. 先把 microSD 插上，再开机。插卡时机很关键： Pocket 4 在关机状态下插卡才能被识别到，开机后再插可能认不到。
  2. 开机后确认它认到了。看屏幕上的剩余容量： 如果显示的是内置 107 GB 的剩余空间，而不是你那张卡的容量，说明它还在写内置。
  3. 在设置里把存储位置切到 microSD（菜单文字以机器固件为准）， 确认剩余容量变成卡上的数字。
  4. 拍一张，立刻回放。这一张是最便宜的验证：回放能看到，说明它真的写在卡上了。 再用读卡器插上电脑，确认文件真的在。
  5. 以后每次开机前都确认一次容量。把这变成习惯，它比任何备份软件都便宜。

五、HEIF / JPEG 与 DNG：格式不同，整理方式不同

你的两台机产出的是两种性质完全不同的文件，混在一起整理会出乱子。

文件来自后缀里面是什么怎么整理
HEIF iPhone Air .heic 已经算好的成片 可当最终素材；若要跨设备、跨软件，导出一份 sRGB 的 JPEG 当「通用版」
JPEG 两台机都能出 .jpg 已经算好的成片，通用性最好 最省事的一种，存、传、打印、发出去都行
DNG Osmo Pocket 4 .dng 传感器原始数据，没有锁死白平衡、没有被压缩 当成负片：不裁不调不导出，单独收好

三条实操上的提醒：

  • 不要靠改后缀来转换格式。把 IMG_1234.HEIC 改名成 IMG_1234.jpg，文件并不会因此变成 JPEG，只是名字变了——很多软件仍然打不开。 真要转换，用系统自带的图片应用或专门的转换工具重新导出。
  • Pocket 4 存「JPEG + DNG」时，文件是成对的。导入时别只挑了 JPEG 就把 DNG 落在卡上——DNG 才是以后想重新调色时唯一的余地。
  • DNG 是开放格式。它不绑定某一个品牌的后期软件，换电脑、换软件、 甚至过几年再打开，都还能用。

还有一个容易出错的细节：后期软件会在原始文件旁边写「旁车文件」 （sidecar，扩展名常常是 .xmp），记录你做的裁剪、曝光调整。 旁车文件和原始文件必须一起搬，否则调整记录会丢—— 所以第三层目录 edit\ 存在的意义，就是把「工程和它的负片」放在一起同步。

六、定期清理与「3-2-1」：一套真的能跑的方案

摄影圈里有个通行做法，叫「3-2-1」备份原则：

  • 3 份素材副本；
  • 2 种不同的存储介质（比如一块硬盘 + 一张卡 + 一个云端，不能是同一块盘上的三个文件夹）；
  • 1 份不在同一个物理地点（家里那份不算数，要有一份在你拿不到的地方）。

在这台 Windows 11 机器上，直接照抄这一套

不装任何第三方软件，只用 Windows 自带的东西：

  1. 建工作区。在 D 盘建一个 D:\Photos， 里面按 年\月\日期_主题 建文件夹。这是你唯一会天天打开的目录。
  2. 第一份：设备 → 电脑。iPhone Air 用 USB 线或「照片」App 导出； Pocket 4 用 USB 3.1 直连或读卡器。全部复制进 D:\Photos， 原片放 raw\，然后按本讲第三节改名。
  3. 第二份：电脑 → 另一个地方。最省事的是开一个 OneDrive 同步文件夹 （Windows 自带客户端，把 D:\Photos 放进去），它同时给你「另一个介质」和 「另一个地点」；或者每周插上移动硬盘，用一条命令把增量文件复制过去：
robocopy "D:\Photos" "E:\Photos-Backup" /E /MIR /R:2 /W:5 /LOG:"E:\backup.log"

关键词：/E 连空子目录一起复制、/MIR 镜像（让两边一致）、 /R:2 /W:5 失败重试两次、/LOG 把结果写进日志—— 有了日志，你才知道上次到底同步了多少个文件。第一次跑完，打开日志看最后一行， 记下来，下周对比这个数字，对不上就说明中间出了问题。

  1. 第三份（可选）：云端。OneDrive 已经覆盖了「不在原地」这一条； 想再多一份，就挂个网盘客户端做纯上传，不要用「同步」模式—— 同步模式会把本机的改动双向传播，万一本机文件坏了会同步到云端。
  2. 校验。备份完随机挑三张打开看看。这是唯一能证明 「备份是好的」的动作——静默失败的备份比没有备份更危险，因为它让你以为自己已经安全了。 更严格的做法是用校验和（checksum）比对两边的哈希值， Windows 自带的 certutil -hashfile 文件名 SHA256 就够。

清理流程：每月十分钟

备份做好之后，才敢清理。顺序是固定的：

  1. 先确认已导入。打开电脑上的那份，随机翻几张，确认文件在、能打开。
  2. 再确认已备份。确认那份已经在第二处（同步的看日志，复制的手动翻一遍）。
  3. 然后才清设备。用设备自带的格式化存储功能（不是文件管理器里的「删除」—— 删除只是让空间显示成空，实际数据还在，占着空间直到被新数据覆盖）清掉卡或机身存储。 Pocket 4 有独立的存储管理菜单，iPhone 则是「设置 → 通用 → iPhone 储存空间」。
  4. 原始文件永远不删。真正可以删的是导出件， 因为它们随时能从原片重新生成。

练习（二十五分钟）：今天就搭好你的备份骨架，之后每张新照片都自动落位。

  1. 五分钟：建好 D:\Photos\2026\10\2026-10-24_练习\， 里面分出 raw / export / select / edit 四个文件夹。
  2. 五分钟：从 iPhone Air 导出今天拍的一组（不超过 20 张），复制进 raw\， 按 日期_主题_序号 改名。先复制，不要从手机里删。
  3. 五分钟：用 Pocket 4 拍 3 张 DNG（或 JPEG+DNG），导入同一目录，同样改名。 注意 DNG 和它的 JPEG 都要在。
  4. 五分钟：把 D:\Photos 放进 OneDrive 同步文件夹（或复制到移动硬盘）， 然后随机打开三张文件，确认两份都能打开。
  5. 最后五分钟：打开 Pocket 4 的存储管理，看一眼剩余容量， 确认它现在写的是内置 107 GB 还是你插的 microSD。把这个数字记在手机备忘录里。

做完这二十五分钟，你就拥有了本课程前十六讲的所有前提—— 拍下来的东西，不会因为你换了手机、丢了卡、或者某天想腾空间而消失。 摄影里有一半的失败，其实不是拍砸了，是弄丢了。

回顾：三个自测

先合上讲义，自己回答，再看核对

1. 你把照片从手机拷到 D 盘，又在 D 盘的另一个文件夹里复制了一遍。这算几份备份？

看答案

算一份。「3 份」要求的是3 个能各自独立存在的地方，不是 3 个文件夹。 D 盘一旦损坏或格式化，这两份会一起消失。「3」里真正有意义的差别是介质和地点的差别： 一块盘 + 一张卡 + 一个云端，哪怕装的是同一批文件，也比三份挤在一块盘上安全得多。

2. Pocket 4 里插了 microSD，怎么确认它真的在往卡上写，而不是还在往内置 107 GB 写？

看答案

四步：关机状态插卡 → 开机 → 看剩余容量是不是变成卡上的数字 → 拍一张并立刻回放。 只看「插了卡」不够——剩余容量若还是内置存储那一栏的数值，就说明它没在往卡上写。 最后那一步是唯一能百分之百确认的办法，因为它验证的是结果而不是设置。 「以为备份了其实没有」比「没备份」更危险：前者会让人停止警惕。

3. 一张 DNG 和它对应的 JPEG，导入时你会怎么处理？为什么不能只留 JPEG？

看答案

两个文件一起留，放进 raw\，尽量不要改动。 JPEG 是算好的成片；DNG 是传感器原始数据，没有锁死白平衡、没有压缩， 是你以后想重新调色、重新构图时唯一的余地。只留 JPEG 等于把「重新处理的可能」永久交了出去。 另外后期软件会在原片旁写旁车文件（如 .xmp），搬移时要和原片一起搬。

这一讲哪里没说清？回到 OpenCode 里直接问你的老师（那个正在运行 teach 的 agent）——它比你更懂你的目标，可以为你重新举例、加练，或跳到你想深入的部分。 它的笔记里已经记着你的两台机器（iPhone Air 与 Osmo Pocket 4， 以及内置 107 GB 和 microSD 这条存储线），随时可以让它把任何一讲改写成你设备上的具体操作。 如果你手上还有外接硬盘或 NAS，也告诉它，它会把「3-2-1」那一段改成你自己的方案。
