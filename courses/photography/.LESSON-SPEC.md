- 读者的机器只有两台：**iPhone Air**（单摄，26mm f/1.6，无超广角无 ProRAW，格式 HEIF/JPEG）

  已在 RESOURCES.md 中已验证可达的链接）。已验证可达的链接见 `courses/photography/RESOURCES.md`。
  **不要发明新的外链**，优先复用 RESOURCES.md 里已有的链接（豆瓣搜索页、Cambridge in Colour、

## 硬性约束
1. **零 JavaScript**。测验一律用原生 `<details>`。
2. **正文 2500–4000 字**（不含 HTML 标签）。讲清"机制 + 真实案例 + 决策链"，不是概念罗列。
3. **每讲至少 1 张内联 SVG 图解**，复杂概念 2 张。SVG 必须：
   - 用 `viewBox="0 0 420 XXX"`（宽度 420，高度按内容 220–320）；
   - **颜色只用 style.css 里已有的 class**：`.f-surface .f-bg .f-accent .f-wash .f-rule .f-ink .f-muted .f-ok .f-bad`
     和 `.s-rule .s-muted .s-faint .s-accent .s-ink .s-ok .s-bad`，
     文字用 `.t-accent .t-muted .t-faint .t-ok .t-bad`。
   - **绝对不许写死颜色**（不许出现 `#xxxxxx`、`fill="red"`、`stroke="black"` 之类）。
   - `<figure class="figure"><svg …><title id="…">…</title>…</svg><figcaption>…</figcaption></figure>`
   - figcaption 里要有「<b>怎么读：</b>」这样的引导，说明这张图该怎么读。
4. **真实照片**只能用 `assets/img/` 里已有的公有领域作品（adams-mt-williamson.jpg、cameron-darwin.jpg、
   curtis-inupiat-family.jpg、hine-power-house-mechanic.jpg、lange-migrant-mother.jpg、
   muybridge-horse-in-motion.jpg、niepce-le-gras.png）。**不要新增图片文件**（需要新图就用内联 SVG 代替）。
   照片用 `<figure class="figure"><img src="../assets/img/xxx.jpg" alt="…">` +
   `<figcaption>…<span class="exif">作者 · 年份 · 摄影</span></figcaption>`。
5. **每讲结构**：h2 分节（4–6 节）→ 一个 `.card` 动手练习（具体、可执行、有时长估计）→
   `.quiz` 三个自测（每题 `<p class="prompt">` + `<details><summary>看答案</summary><p>…</p></details>`，
   答案要讲清"为什么"，不能只给结论）→ `.ask` → `.foot`。
6. **类名只用 style.css 里有的**：`.kicker .lede .toc .card .quiz .prompt .ask .foot .refs .figure .exif
   .pill .split .photo`。不要发明新类名，不要写内联 style（除 `.toc` 那一条 margin 是允许的，
   因为样板里就有）。
7. **不写死颜色在 HTML 里**（style 属性里也不要）。
8. 讲义里凡是"两台机"的差异，**分开写**：iPhone Air 一段、Osmo Pocket 4 一段，不要笼统说"手机"。
9. 术语首次出现时用 `<dl><dt>…</dt><dd>…</dd></dl>` 定义，术语要收进 `reference/0003-glossary.html`
   （这一条不需要你改 glossary，列出你新引入的术语在讲义末尾"新术语"里列一句即可，我会合并）。
10. 末尾不要出现"（待补）""TODO"之类占位。
